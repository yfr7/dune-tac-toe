# Tech Stack

> Technical architecture and tooling for [Dune Tac Toe](prd.md).

## Overview

```
┌─────────────────────────────┐
│   Frontend (Vite + React)   │
│   TypeScript, Tailwind CSS  │
│   Port 5173                 │
├─────────────────────────────┤
│   Generated TypeScript SDK   │
│   (@hey-api/openapi-ts)     │
├─────────────────────────────┤
│   OpenAPI Spec (generated   │
│   by FastAPI)               │
├─────────────────────────────┤
│   Backend (Python + FastAPI)│
│   uv, LangGraph            │
│   Port 8000                 │
├─────────────────────────────┤
│   OpenAI GPT 5.x API       │
└─────────────────────────────┘
```

## Frontend

| Choice | Detail |
|--------|--------|
| **Build tool** | [Vite](https://vitejs.dev/) |
| **Framework** | [React 19](https://react.dev/) with TypeScript |
| **Styling** | [Tailwind CSS v4](https://tailwindcss.com/) + [shadcn/ui](https://ui.shadcn.com/) |
| **State management** | [Jotai](https://jotai.org/) (latest) — atomic state management |
| **API client & types** | [@hey-api/openapi-ts](https://heyapi.dev/) — plugin-based SDK generator; produces typed client (`@hey-api/client-fetch`), TypeScript types, and TanStack Query options from the backend's OpenAPI spec |

### Key Frontend Responsibilities
- Render the game board with [Dune theming](theme.md)
- Manage local game state (board, turns, win detection)
- In Human vs CPU mode, call the backend API after each human move
- Display LLM-generated commentary alongside CPU moves
- **All API request/response types are generated from the backend's OpenAPI spec — never hand-written**

## Backend

| Choice | Detail |
|--------|--------|
| **Runtime** | Python 3.12+ |
| **Package manager** | [uv](https://github.com/astral-sh/uv) |
| **Framework** | [FastAPI](https://fastapi.tiangolo.com/) |
| **Server** | Uvicorn (bundled with FastAPI) |

### Key Backend Responsibilities
- Expose REST endpoints for CPU move generation
- Orchestrate LLM calls via LangGraph
- Validate LLM responses (ensure valid board positions)
- Serve CORS headers for local frontend development
- **Generate strongly typed OpenAPI spec** (FastAPI does this natively from Pydantic models)

### OpenAPI Contract

FastAPI auto-generates an OpenAPI 3.1 spec from Pydantic request/response models. This spec is the **single source of truth** for all data contracts between backend and frontend.

**Spec endpoint:** `GET /openapi.json` (served by FastAPI automatically)

The frontend build pipeline generates TypeScript types and a typed client from this spec (see [API Contract Workflow](#api-contract-workflow) below).

### API Endpoints

#### `POST /api/move`

Request:
```json
{
  "board": [
    ["X", null, "O"],
    [null, null, null],
    [null, null, null]
  ],
  "character": "baron_harkonnen",
  "player_piece": "X",
  "cpu_piece": "O"
}
```

Response:
```json
{
  "move": { "row": 1, "col": 1 },
  "commentary": "You dare claim Arrakeen? How delightfully naive. The Palace is mine now, and soon... everything else."
}
```

#### `GET /api/health`

Returns `{ "status": "ok" }` for basic health checks.

## LLM Layer

| Choice | Detail |
|--------|--------|
| **Orchestration** | [LangGraph](https://langchain-ai.github.io/langgraph/) |
| **Model** | OpenAI GPT 5.x |
| **API** | OpenAI Python SDK via LangGraph |

### Why LangGraph?

For the PoC, a single LLM call would suffice. LangGraph is included to:
- Structure the prompt/response flow as a graph (board state -> prompt assembly -> LLM call -> response validation)
- Provide a foundation for more complex agent behavior in future phases (e.g., multi-step reasoning, memory of past games)
- Make it easy to swap models or add tool use later

### Prompt Strategy

Difficulty is controlled entirely via prompt engineering (see [Game Design - Difficulty](game-design.md#difficulty-via-prompt-engineering)). A single prompt per CPU turn includes:
- The character's personality description
- Difficulty instructions (play optimally, moderately, or poorly)
- Current board state with location names
- Output format instructions (structured JSON)

## API Contract Workflow

The backend and frontend stay in sync through generated OpenAPI types:

```
Backend (FastAPI + Pydantic)
        │
        ▼
  openapi.json  ← auto-generated by FastAPI
        │
        ▼
  @hey-api/openapi-ts  ← generates TypeScript types, SDK client, and query options
        │
        ▼
  @hey-api/client-fetch  ← typed fetch client (runtime)
        │
        ▼
  Frontend (React + TypeScript)
```

| Step | Tool | What it does |
|------|------|-------------|
| 1. Define models | Pydantic (backend) | Request/response schemas defined as Python models |
| 2. Generate spec | FastAPI | Auto-generates `openapi.json` from Pydantic models |
| 3. Generate SDK | `@hey-api/openapi-ts` | Generates TypeScript types, typed SDK functions, and TanStack Query options from the spec |
| 4. Runtime client | `@hey-api/client-fetch` | Thin fetch-based HTTP client used by the generated SDK |

### Hey API Plugins

| Plugin | Purpose |
|--------|---------|
| `@hey-api/typescript` | Generate TypeScript types from OpenAPI schemas |
| `@hey-api/sdk` | Generate typed SDK functions (per-endpoint) |
| `@hey-api/client-fetch` | Fetch-based runtime client |
| `@tanstack/react-query` | Generate `queryOptions()` / `mutationOptions()` for TanStack Query v5 (optional) |

### Usage

```bash
# Generate SDK from the running backend (or a saved spec file)
npx @hey-api/openapi-ts \
  -i http://localhost:8000/openapi.json \
  -o src/api/generated \
  -c @hey-api/client-fetch
```

```typescript
// src/api/client.ts
import { client } from "@hey-api/client-fetch";

// Configure the base URL once
client.setConfig({ baseUrl: "http://localhost:8000" });
```

```typescript
// Usage — fully typed SDK function generated from the spec
import { postApiMove } from "./api/generated";

const { data, error } = await postApiMove({
  body: { board, character: "baron_harkonnen", player_piece: "X", cpu_piece: "O" },
});
// data and error are fully typed from the OpenAPI spec
```

**Rule:** Frontend code must never hand-write types for API request/response shapes. All such types come from the generated SDK in `src/api/generated/`.
